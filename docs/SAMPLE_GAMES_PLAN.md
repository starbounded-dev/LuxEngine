# Sample games plan (M10, issue #46)

Point-in-time plan. M10 is one board item, X6 #157 ("Samples for users, separate from the engine test bed"); it is split into four checkpoints in dependency order.

## Decisions

- **Two small games, chosen with the owner (2026-11-19):** **Coin Run** (3D: a third-person character on platforms and ramps, coins, a goal, particles, UI) and **Pixel Hop** (2D: a tilemap platformer with a Box2D player, sprite animation, coins, an enemy, UI, a second level).
- **Made only with what the release zip holds.** Every asset is something the editor can make or import: scenes, materials, prefabs and tilemaps as the editor saves them, C# scripts against the public API, the default meshes, textures, sprite sheets and sounds generated by the scripts in `tools/samples` (original work, no third-party art or audio, so nothing to license). Nothing in a sample reads the engine's source tree.
- **Separate from the test bed.** `Editor/LuxSampleProject` stays in the repository for development (benchmarks, golden scenes, the DDGI folder) and stops being shipped. The release zip gets `Samples/CoinRun` and `Samples/PixelHop` instead (catalog §7).
- **The acceptance test is the point.** `tests/samples/run_samples.py` takes the staged zip layout (no source tree), opens each sample in the editor unattended, exports it with the Dist editor, runs the exported game with scripted input, and requires the game to reach its end state (all coins, the goal) and report it. Windows and Linux.

## Checkpoints, in order

1. **S1** The zip ships `Samples/` and not the test bed; the sample generators and the layout.
2. **S2** Coin Run (3D).
3. **S3** Pixel Hop (2D).
4. **S4** The acceptance test on the staged zip layout, Windows and Linux, and the docs ("Your First Game" points at the samples).
